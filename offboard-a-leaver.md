# Offboard A Leaver

How we close out someone's time in the group so that their data, code and responsibilities stay usable. Written after [[felix-achterberg]] left in August 2025 and his single-cell data took weeks to find. Owner: [[priya-raman]].

## Steps

1. **When notice is given.** Priya agrees the last day with [[aisha-bello]] and opens an offboarding tab in the checklist.
2. **Six weeks before.** The leaver lists their datasets, code repositories, scheduled jobs and responsibilities. Each gets a new owner in [[who-owns-what]].
3. **Four weeks before.** Unfinished analyses written up as notes in the vault, linked from the project, with pipeline versions and data locations. Code pushed to group repositories, not personal ones.
4. **Two weeks before.** [[yara-castellanos]] reviews data access; personal Halyard directories moved to project space or deleted with the new owner's agreement.
5. **Last week.** Handover meeting with each new owner. Authorship expectations for papers in progress written down ([[authorship-and-credit-guidelines]]).
6. **Last day.** Access ends: Halyard, GitLab, data, building, as set in the [[group-data-management-plan]]. Exit conversation with Ines; HR exit interview with Aisha.

## Verification

One month after, the new owners confirm they found everything. Anything missing goes into this procedure as a new step.

## Guardrails

Do not delete a leaver's directories until the new owner signs off in writing.
